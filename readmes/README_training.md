# Standalone VLA Training Instructions


## Installation

1. Install openpi from GitHub: [openpi GitHub](https://github.com/Physical-Intelligence/openpi).
    - If you want to log runs online with Weights&Biases, you may need to upgrade the wandb package to support longer API keys: `source openpi/.venv/bin/activate && uv pip install -U wandb`

2. Modify openpi install with RobotGPT integration:
    - Run `git clone https://github.com/ronypepper/RobotGPT.git`
    - Run `cp -r RobotGPT/openpi/robotgpt openpi/src`
    - Edit openpi/src/openpi/training/config.py:
        - Add "from robotgpt.train_configurations import get_robotgpt_train_configs" to bottom of imports
        - Add "\*get_robotgpt_train_configs()," as last entry to the _CONFIGS list, right after "*polaris_config.get_polaris_configs(),"


## Usage

The standard pipeline has four steps:
1. Copy an HDF5 dataset obtained in simulation or with a real robot to the "robotgpt_output/datasets/hdf5/" directory.  
2. Convert the HDF5 dataset to a LeRobot dataset using the "utils/convert_hdf5_to_lerobot.sh" script.  
3. Train a VLA model on it using the "utils/train_openpi_model.sh" script.
4. Serve the policy for evaluation with:
```
source openpi/.venv/bin/activate

XLA_PYTHON_CLIENT_MEM_FRACTION=0.5 python -m robotgpt.serve_policy \
--config TRAIN_CONFIG_NAME \
--checkpoint_dir checkpoints/TRAIN_CONFIG_NAME/EXPERIMENT_NAME/CHECKPOINT \
--repo_id HUGGING_FACE_USERNAME/EXPERIMENT_NAME
```

For details about the shell scripts arguments, run `XXXXXXX.sh --help`.

> You may need to make the scripts executable by running:\
> `chmod +x convert_hdf5_to_lerobot.sh train_openpi_model.sh`\
> inside "RobotGPT/utils/".


## Add a new robot to training

The following steps need to be done to add a new robot embodiment:
1. Define a new datatset conversion file in "RobotGPT/openpi/robotgpt/hdf5_interfaces/", which implements:
    - The *get_data_dimensions_<ROBOT_NAME>* function, defining action and observation dimensions for use by the dataset conversion script.
    - The *process_hdf5_frame_<ROBOT_NAME>* function, which converts actions and observations from an hdf5 dataset to the format expected by openpi for training. Used by the dataset conversion script.
2. Register the *get_data_dimensions_<ROBOT_NAME>* and *process_hdf5_frame_<ROBOT_NAME>* functions in "RobotGPT/openpi/robotgpt/hdf5_dataset_interfaces.py" in the *HDF5_DATASET_INTERFACE_FCTS* object under a name for the new robot type.
3. Define a new openpi integration file in "RobotGPT/openpi/robotgpt/train_configs/", which implements:
    - The *<ROBOT_NAME>Inputs* class, which maps received observations (from robot interface or dataset) to openpi's internal format.  
    (If working with simulation, this must match the observation processing function defined in step 1 of [Add a new robot to simulation](README_simulation.md#add-a-new-robot-to-simulation).)
    - The *<ROBOT_NAME>Outputs* class, which remaps and truncates actions generated by openpi policys.
    - The *<ROBOT_NAME>DataConfig* class, which defines additional data transformations and utilizes the previous two classes.  
    (If working with simulation, this must match the action processing function defined in step 1 of [Add a new robot to simulation](README_simulation.md#add-a-new-robot-to-simulation).)
    - The *<ROBOT_NAME>_configs* list, containing *TrainConfig* instances that define configurations for training and using openpi policies. The *<ROBOT_NAME>DataConfig* class is defined here as a data interface, as well as additional parameters defining the openpi model used, as well as training hyperparameters.
4. Register the *<ROBOT_NAME>_configs* list in "RobotGPT/openpi/robotgpt/train_configurations.py" by extending the *all_cfgs* object with the new configs list.

See existing robot embodiment implementations for more detail.
